# 작업 마무리: 커밋 → 푸시 → PR

## 1. 확인
- `git status -sb`로 브랜치와 변경 파일을 본다.
- **`main`에 있으면** 작업 내용에 맞는 새 브랜치를 만든다 (`git switch -c add-xxx`). `main`에 직접 커밋하지 않는다.
- 변경 파일 중 비밀번호, 토큰, `.env`, 개인 데이터가 있으면 멈추고 사용자에게 알린다 (공개 저장소).
- 변경이 서로 다른 기능 여러 개라면 **기능 1개 = PR 1개**로 나눌지 사용자에게 묻는다.

## 2. HANDOFF.md 갱신
- 맨 위의 `최종 업데이트` 날짜를 오늘로 바꾼다.
- "핵심 요약"의 완료/다음 항목, "한 일" 표(새 번호로 추가), "남은 것" 표의 상태와 우선순위를 실제에 맞게 고친다.
- 새로 알게 된 주의사항이 있으면 "알게 된 점"에 한 줄 추가한다.
- "새 세션 첫 메시지"가 다음 할 일을 가리키는지 확인한다.

## 3. 커밋과 푸시
- 관련 파일만 `git add` 한다 (`git add -A`는 쓰지 않는다).
- 커밋 메시지: `docs:` / `feat:` / `fix:` / `ci:` 접두어 + 짧은 영어 요약. 대화에서 안내된 attribution 줄(Co-Authored-By)을 끝에 붙인다.
- `git push -u origin <브랜치>`

## 4. PR
- `gh pr create --base main`으로 만든다. 제목과 본문은 한국어로 쓴다.
- 본문 구성: `## 변경 내용` (불릿 2~4개), 필요하면 `## 확인 방법`, 이슈가 있으면 `Closes #번호`. 끝에 대화에서 안내된 PR attribution 줄을 붙인다.
- PR 링크를 알려 주고, **Merge는 사용자가 GitHub 웹이나 앱에서 직접 한다**고 안내한다. Merge가 끝나면 `/after-merge`로 정리한다.
